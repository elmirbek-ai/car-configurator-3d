# Stage 4.1 — Toyota Camry 2018 интеграциясынын техникалык планы

**Статус:** пландоо гана; Camry азыр негизги конфигураторго кошулган жок. **Чечим:** архитектуралык ишти баштоого GO; Camry функцияларын жалпы колдонуучуга ачууга азырынча NO-GO. Төмөндөгү «ырасталды» glTF түзүмүн жана учурдагы кодду текшерүүгө тиешелүү; браузердеги көрүнүштүн же конфигурация функциясынын иштешин өзүнөн өзү ырастабайт.

## 1. Далилдер жана чектер

- Негизги модель `public/models/CarConcept.glb` бар; Camry талапкери `public/models/candidates/ToyotaCamry2018_WheelLOD_v1.glb` бар, **34 196 580 байт / 32.612 MiB**, SHA-256 `7D7A4E7AC2BFE1C71E83CB3BB5059E03C56EB71AF6D1DD666E661537E595CD14`. Бул файлдын glTF JSON бөлүгү ушул планда кайра окулду: **346 node, 158 mesh, 158 primitive, 30 material, 14 texture/image**. Stage 3.6 аудитинде **875 294 triangle** өлчөнгөн (`src/CamryPreview.tsx:10-15`); бул планда triangle кайра эсептелген жок.
- Кабыл алуу критерийлери `docs/vehicle-asset-evaluation.md:54-64`: desktop ≤15 MiB/250 000 triangle/150 draw call/64 MiB GPU texture; mobile ≤8 MiB/120 000 triangle/100 draw call/32 MiB GPU texture. Camry азыр файл жана triangle чегинен кыйла жогору. Browser FPS, draw call жана GPU memory боюнча ушул планда жаңы өлчөө жок.
- Stage 3.3 геометрия далили `codex-reports/history/20261107-151654-231340.md:31-68`; Stage 3.8 материал далили ушул иш башталганда `codex-reports/history/20261107-174104-194344.md:9-58` болгон архивге негизделет. Акыркысында corrected PBR браузерде визуалдык текшерилбегени так жазылган (`codex-reports/history/20261107-174104-194344.md:65`). Архив көчүрмөсү ушул документте туруктуу далил катары көрсөтүлдү.
- Camry GLB башындагы толук node жолу `Sketchfab_model/toyota camry 2018.fbx/RootNode/...`; мурдагы аудиттеги `P/...` — ушул префикстин кыскартылган белгиси. Төмөнкү таблицада `RootNode`'дон кийинки жол берилет; runtime `MeshBinding.nodePath` үчүн **scene root'тон башталган толук жол** жана primitive index `0` колдонулсун (`src/vehicleDescriptor.ts:8-18`). Node/mesh индекстерин негизги ачкыч кылбоо керек: WheelLOD'до mesh индекси мурдагы оригиналдан өзгөргөн.
- Булак `+Y` өйдө, `+Z` алды, `−Z` арты. Stage 3.3 өлчөгөн bounds: min `(−1.06191, −0.00341, −2.48150)`, max `(1.06218, 1.43833, 2.41133)`; өлчөм `2.12408 × 1.44174 × 4.89283` **source unit**. `metersPerSourceUnit` азыр белгисиз; бул сандарды метр деп жазууга болбойт (`src/vehicleDescriptor.ts:55-71`). Булактагы `WHEEL_L*` +X, `WHEEL_R*` −X; descriptor'дун left/right мааниси дүйнөлүк огун жана көрүү багытын текшерген соң гана берилет (`codex-reports/history/20261107-151654-231340.md:51`).

## 3. Сунушталган келишим жана компоненттер

`src/vehicleDescriptor.ts:1-153` учурда толук текшерилген унаа үчүн ылайыктуу contract: orientation, mesh binding, plate/spoiler anchor, төрт `WheelFitment`, feature flags, metrics, license. Аны экинчи, атаандаш `VehicleDescriptor` менен алмаштырбоо керек. Керектүү так кеңейтүүлөр:

1. `VehicleFeatureFlags` (`:95-105`) ичинде `frontBumper`/`rearBumper` өңдүү эки flag; азыркы типте бампердин өз алдынча өзгөрүүсү жок. `PartMapping`'ге ар mapping'дин далил статусун (`geometryVerified`, `semanticVerified`, `runtimeVerified`) кошуу же ошол далилди өзүнчө registry метамаалыматында кармоо. `mapped` «функция иштейт» дегенди билдирбейт.
2. `VehicleRegistry` үчүн чакан discriminated жазуу: `{ status:'legacy-ready', id:'concept-gt', adapter:'concept', label, existingFeatures }`, `{ status:'candidate', id, label, glbUrl, audit, unavailableReasons }` жана `{ status:'ready', descriptor: VehicleDescriptor, adapter:'camry' }`. Concept азыр иштейт, бирок анын толук `VehicleDescriptor` талаалары аудиттен өткөн эмес; аны `ready` descriptor менен жасалма толтурбоо керек. Camry'ге да жалган `metersPerSourceUnit`, anchor же drawCalls жазылбасын. Candidate жалпы UI'да disabled/preview-only болсун. Толук текшерилгенден кийин гана `ready` жазуусуна өтөт.
3. `VehicleSelector` (`src/App.tsx` ичинде же чакан `src/components/VehicleSelector.tsx`) registry'ден аталыш/статус алат. `legacy-ready` жана `ready` унааны тандайт; candidate үчүн эмне жетишпегени кыска көрсөтүлөт. Тандоо state'и source of truth; компоненттерге `vehicleId`, активдүү config жана feature flags берилет.
4. Сахнада чакан dispatcher: `ConceptSceneAdapter` учурдагы `CarScene` жолун сактайт; `CamrySceneAdapter` Camry URL'ди жана `MeshBinding` жолдорун гана колдонот. Унаалардын материал/дөңгөлөк/номер/камера иши ар адаптерде же чакан тиешелүү helper'де болот. Жалпы `Canvas` shell кийин тесттер далилдесе гана бөлүнсүн; азыр эки loader lifecycle'ын күч менен бириктирүү зарыл эмес.
5. `CamryMaterialAdapter` preview'деги **оригиналга тийбеген** corrected PBR негизин көчүрүп, `Carpaint`, `Glass`, `GreyWheel` ролдору боюнча clone'дорду түзөт. Капот, арткы/алдыңкы бампер өзүнчө түс алса, shared `Carpaint` материалынан **mesh/role боюнча өз owned clone** керек (`src/CamryPreview.tsx:104-140`; `src/components/CarScene.tsx:183-212`). `Glass_LIGHT`, `RedGlass`, head/taillight башка ролдор, айнек tint'ине кирбейт (`codex-reports/history/20261107-174104-194344.md:15-38,48`).
6. `CamryWheelAdapter` алгач original rim'дин `GreyWheel` материалын гана иштетет. Custom design үчүн төрт `WheelFitment`, axle багыты, hubcap/brake бөлүнүүсү жана визуалдык clearance керек. Concept `WheelRims` абсолюттук өлчөмдөрүн/айлануусун көчүрбөө.
7. Plate жана spoiler компоненттери **geometry/UI гана** бөлүшө алат; `Pose3`, mount өлчөмдөрү жана бекитүү геометриясы model-specific. Concept'тин номер координаттары жана спойлер геометриясы өзгөрүүсүз калсын. Camry anchor `null` болсо тиешелүү функция `false`; UI муну түшүндүрөт.
8. Камера абалында viewer target жана аралык model bounds'тан чыгарылып, `front/rear/left/right/top/free` багыты orientation аркылуу берилсин. OrbitControls interaction, transition cancellation жана `frameloop='demand'` invalidation текшерилсин. Camry preview'деги auto-fit (`src/CamryPreview.tsx:263-310`) таяныч болот; preview'де top/free жок.

**Келишимди толтуруу эрежеси:** `ready` descriptor түзүүдө URL/hash, node path/primitive/material, source→viewer transform, өлчөм, feature-gate, лицензия жана метрика бирге валидацияланат. `src/vehicleDescriptor.ts:121-127` талап кылган `drawCalls`/GPU texture баасын байкоо жок болсо 0 же ойдон чыгарылган санга алмаштырбоо; Camry аудит жыйынтыгы `candidate` бойдон турсун. Concept `legacy-ready` жолун толук аудит даяр болгонго чейин сактоо — учурдагы иштешти коргоочу чектелген өткөөл чечим.

## 6. Дайын, сактоо жана ресурс өмүрү

**Сунушталган v2 форматы:** `car-configurator-mvp-v2` ачкычы астында `{schemaVersion:2, activeVehicleId:'concept-gt', configurations:{'concept-gt':{...}, 'toyota-camry-2018':{...}}}`. `CarConfiguration`'га `vehicleId` кошуунун ордуна v2 документте жана active selection'да сактоо оңой; бирок user талабы «vehicleId in saved configuration» болгондуктан **ар бир конфигурация жазуусу** `{vehicleId, values}` болуп, экспортто да `vehicleId` милдеттүү болсун. Бул катмар `src/types.ts` учурдагы `CarConfiguration` талааларын бузбай кеңейтет. Concept default азыркы `DEFAULT_CONFIG` (`src/types.ts:15-16`), Camry default өзүнчө такталат; белгисиз функциялардын нейтралдуу маанилери гана берилет, UI колдонуусуна тыюу салынат.

Окуу тартиби: жарактуу v2 бар болсо анын schema/version/vehicle ID/ар талаасын runtime текшерүү; жараксыз же жок болсо v1 (`src/App.tsx:6,26-31`) окуп `validateStoredConfig` (`src/types.ts:32-52`) аркылуу **Concept гана** деп миграциялоо. v2 ийгиликтүү жазылмайынча v1'ди өчүрбөө; storage exception'ду кармап in-memory default менен иштөө. Автоматтык migration `Save` басылмайынча мурдагы save жүрүмүн өзгөртпөшү керекпи — implementation алдында чечилсин; эгер автоматтык жазылса idempotent жана v1 source сакталышы шарт. Белгисиз vehicleId'ди fallback Concept кылып сактабастан, UI'га ката көрсөтүп, маалыматты жоготпоого аракет кылуу. Unsupported Camry талаалары persisted болушу мүмкүн, бирок adapter'ге берилбесин; feature жеткиликтүү болгондо кайра валидациялансын. Reset активдүү `{vehicleId,values}` жазуусун гана өчүрүп, ошол унаанын default'ун коёт; storage remove/write катасын билдирет. Экспортто `schemaVersion`, vehicleId, model asset version/hash, конфигурация жана атрибуцияга шилтеме болсун; импорт функциясы азыр талап кылынбайт.

**Жүктөө/тазалоо:** бир учурда бир гана активдүү GLB. Concept `useGLTF` кэши (`src/components/CarScene.tsx:175-180`) original geometry/texture'ларын сактайт; clone material/CanvasTexture/аксессуарды гана dispose кылат (`:289-293,354`). Camry preview `fetch + GLTFLoader.parseAsync` жана AbortController/очередь үлгүсүн (`src/CamryPreview.tsx:182-225`) колдонууга болот, бирок production switch'те эски сцена detach болгон соң owned geometry/material/texture'ларды бир жолу гана dispose кылуу, кеч келген parse жыйынтыгын өзүнчө dispose кылуу, source жана corrected material экөөнү тең эсептөө керек. R3F `<primitive dispose={null}>` учурда explicit ownership'ге таянат (`src/CamryPreview.tsx:260`). Shared PMREM/renderer ресурстарын asset cleanup'уна кошпоо; PMREM environment өз lifecycle'ында (`:352-377`). State transition'дун алдында жаңы car load error чыкса учурдагы Concept scene иштеп калышы же так error state болушу керек; эки модель бир убакта GPUда калбасын. StrictMode mount/unmount жана тез switch үч жолу менен текшерилсин.

## 9. Текшерүү жана regression барагы

- **Static:** descriptor бардык `nodePath`/primitive/material'дарды WheelLOD glTF JSON менен салыштырат; жетишпеген mapping'де feature өчөт жана ката көрүнөт. Белгисиз mapping же `null` anchor нөл координатка түшпөйт. Asset URL'дер HTTP 200; файл hash/bytes asset revision менен дал.
- **TypeScript/build:** ар этапта `npx tsc --noEmit`, `npm run build`; бул пландоо тапшырмасында иштетилген жок. Environment failure өзүнчө жазылат.
- **Storage:** v1ден Concept көчөт; v2 бир эле жолу миграцияланат; corrupt JSON, туура эмес vehicleId/enum/plate, denied/quota localStorage; эки унаага өзүнчө Save/Reset/Export; unsupported feature config scene'ге жетпейт.
- **Switch/loading:** Concept→Camry→Concept жана тез кайталоо; бир модель гана жүктөлөт; fetch abort/late parse; retry, 404 жана WebGL error; React StrictMode'до console lifecycle катасы жок. `renderer.info.memory`/browser performance trace аркылуу cleanup тенденциясын өлчөө; кэшке байланыштуу туруктуу базаны агуу деп атабоо.
- **Visual:** бирдей камера/жарык менен Concept учурдагы көрүнүшү; Camry original/corrected салыштыруу; body түс/үч finish, алты терезенин tint'и, lights/chrome/interior өзгөрбөшү; hood/bumper boundary. Экран сүрөттөрү front/rear/left/right/top/three-quarter.
- **Wheel:** төрт center жана bounds/source transform, rim/tire/brake өз-өзүнчө; finish жана custom design болсо бардык камерада close-up; RR кошумча детал. Бул далил жокто custom rim жабык.
- **Plates/spoiler:** Concept front `[0,0.40,2.42]` жана rear `[0,0.31,-1.94]` өзгөрбөйт; Camry жаңы front/rear anchor pose, mount size, кадимки номер менен collision, KG текст синхрон; spoiler эки contact point/shadow/clearance.
- **Camera/UI:** алты preset, smooth transition, кол менен orbit/zoom, top view, mobile viewport fit жана accordion keyboard/aria-pressed; feature өчүк себеби түшүнүктүү.
- **Performance:** cold/warm load убактысы, transfer bytes, triangle, draw calls, frame time/FPS, GPU texture memory estimate, renderer memory after switch; desktop жана mobile профилинде өзүнчө. Stage 3.6'дагы **32.612 MiB/875 294 tri production бюджетке туура келбейт**; FPS жакшы көрүнсө да transfer/memory gates өзүнчө чечилет.

## 10. Тоскоолдуктар, тобокел жана GO/NO-GO

**Чечилбегендер:** brake disc/caliper separation; hubcap'тын функциясы жана RR кошумча детал; төрт wheel fitment жана физикалык scale; hood/front/rear bumper толук семантикалык чеги; эки KG plate anchor жана заводдук номер менен конфликт; spoiler mount; L/R viewer convention; corrected PBR, glass/light көрүнүшү жана camera fit'тин браузердик тастыгы; texture GPU bytes, draw calls жана FPS; Toyota логотиби/соода белгисинин укугу; веб бюджет үчүн кошумча оптимизация. GLB metadata DR1KING100K/CC BY 4.0 деп айтат, бирок бардык үчүнчү тарап укугун ырастабайт (`codex-reports/history/20261107-151654-231340.md:23,111`). Preview атрибуциясын сактоо керек (`src/CamryPreview.tsx:526-528`).

**GO — архитектуралык кодго:** 1-этаптагы registry/candidate contract азыр башталышы мүмкүн; Concept behavior жана KTX2 loader сакталат. **NO-GO — Camry'ни public production selector'до ready кылууга:** жогорудагы укук/бюджет/браузер QA жана минимум иштетилчү функциялардын mapping acceptance шарттары аткарылмайынча. Айрым кошумча функциялар далил жетмейинче өчүк бойдон кала алат; бирок эки plate же spoiler'ди ойдон чыгарылган anchor менен иштетүүгө жол жок. Browser QA өлчөө жакшы чыкса да бул файл/triangle чегинин автоматтык жактырылышы эмес — өзгөчө exception жазуу жүзүндө негизделиши керек.

**Сунушталган тартип:** registry/candidate → v2 storage/selector → isolated Camry loader/camera/material preview → browser/Blender mapping жана performance/укук текшерүүсү → далилденген paint/tint/wheel finish → verified bumper/hood/plate/spoiler → brake/fitment далилденсе wheel design → asset gate жана regression. **Биринчи коопсуз coding task:** `src/vehicleDescriptor.ts` келишимине bumper flags/evidence статусун чакан кошуп, өзүнчө registry'де Concept `legacy-ready`/Camry `candidate` түзүү; scene жана негизги UI азырынча ошол бойдон калсын. **Негизги учурдагы функциялык коркунуч:** CarConcept plate координаттары, `useGLTF`/KTX2 ownership, Concept wheel өлчөмү жана v1 save'дин Camry'ге жаңылыш колдонулушу.
